用 Obsidian 这几年，总有些小地方不顺手。社区插件找不到合适的，就自己上手写。攒到现在已经有 5 个了，其中 4 个最近整理并开源了出来。这篇文章做个汇总，主要也是怕自己忘了每个插件是干嘛的。

## KazooTTT Vault Timeline

> 把整个 vault 的笔记变成一个类似 flomo / 微博的时间线。

- 仓库：[KazooTTT/obsidian-timeline](https://github.com/KazooTTT/obsidian-timeline)
- 插件 ID：`kazoottt-obsidian-timeline`

初衷是想要一个 flomo 那样的"流水"视角：所有笔记按创建或更新时间倒序排开，顶部就是一个编辑器，随手写一条就存成一条笔记（自动按时间命名，统一放进 `Timeline/` 文件夹）。编辑器直接复用了 Obsidian 原生的 Live Preview 内核，所以 `[[链接]]`、`#标签` 补全、粘贴图片这些体验和普通笔记一致。

还支持关键词和日期范围搜索、Excalidraw 笔记直接渲染画布预览、长文折叠、滚动加载。

一个教训：这个插件最初的 ID 是 `obsidian-timeline`，和社区市场里一个同名插件撞了 ID，结果某天被对方整个覆盖安装，时间线"神秘消失"。所以自己的插件 ID 一定要起得独一无二，最好带上个人前缀。

## Periodic Calendar Page

> 主编辑区全屏的周期笔记日历，补齐官方 Calendar 插件不支持月报/季报/年报的短板。

- 仓库：[KazooTTT/obsidian-calendar-page](https://github.com/KazooTTT/obsidian-calendar-page)
- 插件 ID：`periodic-calendar-page`

官方 Calendar 插件只支持日记和周报，还只能待在侧边栏。这个插件把日历搬进主编辑区，完整支持 Periodic Notes 的日记、周报、月报、季报、年报五种周期，带日/年/多年三层缩放视图，以及一个按年统计写作量的"记录统计"页（条数、字数、记录天数的柱状图）。

## Obsidian Toolkit

> 个人命令合集插件，以后零散的小命令都往这里塞。

- 仓库：[KazooTTT/obsidian-toolkit](https://github.com/KazooTTT/obsidian-toolkit)
- 插件 ID：`obsidian-toolkit`

目前只有一组功能：一键把当前笔记的标题大纲复制到剪贴板，支持两种格式——纯 Markdown 标题行，或者 `tree` 命令风格的层级树（根节点是文件名，跳级的标题会用 `(无标题)` 占位，方便发现层级问题）。写文章目录、贴 Issue、发给 AI 看结构都很好用。

定位是"工具箱"：以后再有小的自用命令需求，就继续加进这个插件，而不是每个都开新坑。

## Thino Linter Guard

> 防止 Linter 在保存时污染 Thino 的虚拟编辑器。

- 仓库：[KazooTTT/thino-linter-guard](https://github.com/KazooTTT/thino-linter-guard)
- 插件 ID：`thino-linter-guard`

这是个小而具体的修复：在 Thino（Memos）视图里按 `Cmd+S` 时，Obsidian Linter 会误以为当前文件是 vault 根目录的 `index.md`，然后往里面塞 frontmatter。这个插件在 Thino 视图激活时让 Linter 跳过检查，保存时临时禁用再恢复。如果你也遇到 `index.md` 顶部莫名多出 YAML 的情况，就是它干的。

## 已停用：KazooTTT Blog Publisher

还有一个 `kazoottt-blog-publisher`，是把当前笔记一键发布到旧版博客（自建 API）的插件。博客迁移到现在的 GitHub Issues 方案后它就退役了，仓库保持私有，仅作纪念。现在从 Obsidian 发文章的流程是：写好笔记后用 `gh issue create` 发布为带 `blog:publish` 标签的 Issue——这篇文章就是这样发出来的。

## 小结

几个共同的经验：

- 插件 ID 加个人前缀，避免和社区插件撞车
- 源码、文档、BRAT release 分开放：README 写清楚"这个插件是干嘛的"，不然半年后自己都想不起来
- 小插件不可怕，解决一个具体问题就值得存在
