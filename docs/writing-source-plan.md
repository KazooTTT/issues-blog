# 写作来源标签：计划与规则

状态：已创建来源标签并完成存量初标，作者已确认部分条目；列表与详情页标题旁的独立来源徽章已在本地实现，尚未部署。其余规则与发布文档同步待完成。

## 目标与范围

让读者了解文章最终正文主要由作者写作，还是由 AI 生成。来源标记说明写作方式，不代表内容质量；所有文章仍由作者审核并承担发布责任。

首版使用普通 GitHub 内容标签，保留现有标签页与筛选；列表通过独立来源徽章展示，不增加专门的数据字段：

| 标签 | 定义 |
| --- | --- |
| 人工写作为主 | 作者完成最终正文的主要论述与表达，AI 仅提供辅助，或 AI 草稿已被作者实质性重写。 |
| AI 写作为主 | AI 生成最终正文的主要论述或表达，作者主要提供素材、提示、筛选、核验与局部修改。 |

标签不使用 `blog:` 前缀，因为现有系统会隐藏该前缀的系统标签。这两个标签属于来源说明，使用现有内容标签机制展示；不能替代“随笔 / 笔记 / 总结”导航标签。

## 判定规则

1. 根据真实写作过程与最终正文判定，由作者自行标注，不使用 AI 检测器，不由发布脚本猜测。
2. 主要看正文的核心论述、段落组织与最终措辞由谁完成，不机械计算字数比例。提供原创经历或原始材料，并不自动等于人工主写。
3. 人工写完正文后，用 AI 校对错字、调整格式、建议标题、检索资料或局部润色，通常仍为“人工写作为主”。
4. 作者提供笔记、经历或提纲，由 AI 扩写、整理成文章，最终保留其主要段落和表达，标为“AI 写作为主”。仅逐句审核或调整少量措辞不改变归属。
5. AI 提供草稿，但作者重新组织核心论述，并用自己的表达重写主要正文，可标为“人工写作为主”。
6. 已知 AI 参与主要正文、但两者贡献难以区分时，先重新核对写作过程；仍难判断则采用“AI 写作为主”，正文可补充一句具体说明，例如“本文由我的原始笔记经 AI 整理，我核验并修改后发布”。历史文章写作过程无法追溯属于“来源未知”，保留未标注，不据此归为 AI 主写。
7. AI 生成配图或示例代码，不自动决定正文来源；需要说明时，在图注或相应段落单独注明。
8. 来源标签只描述当前正文。后续大幅重写导致主要写作方式变化时，替换标签；轻微修订无需更改。

## 发布与历史文章

- 规则启用后，新发布文章必须且只能选择一个来源标签，同时保留 `blog:publish`、至少一个导航标签和按需添加的主题标签。
- 两个来源标签不能同时存在；发布前人工检查，首版不新增阻断构建的自动校验。
- 历史文章逐篇确认后补标，不批量推定为人工主写。未标注表示“尚未标注”，不能解释为人工主写；暂不增加第三个标签。
- 来源标签不改变作者、发布资格、首次发布时间、精选或撤回规则。
- 首版应用于文章；About 固定页面和运动复盘暂不强制标注。
- Obsidian 标签不会自动成为 Issue 标签；发布时通过 `gh --label` 或 GitHub 网页明确选择。

## 存量数据处理

### 范围与启用边界

实施时记录规则启用时间，以首次获得发布资格的时间区分新文章与存量文章，不能用 Issue 创建时间或旧博客迁移时间代替。启用前已发布的文章属于存量；撤回后重新发布仍属于同一篇存量文章。

盘点仓库所有者的文章 Issue，包括 Open 和 Closed，分别记录已发布、撤回与草稿。About、运动复盘和其他人的 Issue 不纳入本次补标。优先处理当前已发布文章；草稿首次发布时按新规则选标签，撤回文章在再次发布时顺带核对来源。

旧博客迁入的文章仍逐篇判断当前正文来源。D1 来源标记只能证明迁移来源，原始发布日期只能证明时间，两者均不能直接证明人工写作；不设“某年以前一律人工”的推定规则。

### 盘点与决策清单

先生成只读清单，再决定补标。清单至少记录：Issue 编号、标题、URL、发布状态、首次发布时间、现有标签、拟标来源、判断依据、处理状态。判断依据只记录简要结论，不复制私人笔记或 AI 对话到公开仓库。

| 存量情况 | 处理 |
| --- | --- |
| 作者确认当前正文主要由自己完成，或原稿/版本记录足以确认 | 补“人工写作为主” |
| 作者确认主要正文由 AI 生成，或有明确生成记录 | 补“AI 写作为主” |
| 记不清写作过程，缺乏可核实记录 | 保留未标注，清单记录“来源未知” |
| 已有一个来源标签 | 复核后保留；与事实不符时替换 |
| 同时存在两个来源标签 | 列为冲突，确认后只保留一个；不能自动择一 |

作者对实际过程的确认可作为判断依据，不要求每篇都提供留存材料。文风、发布时间、代码或配图的存在都不能单独作为来源证据。

### 分批执行与恢复

1. 保存待修改 Issue 的原始标签快照，输出拟新增、拟移除标签的预览；只有清单中已确认的文章进入执行批次。
2. 先处理少量来源明确的文章，覆盖两种标签（没有可确认的实例时不强行凑齐），验证部署和展示，再逐批补标；首页精选和近期文章优先。
3. 只增删这两个来源标签，保留其他标签、正文、状态、迁移标记与发布标签。不要通过移除再添加 `blog:publish` 实现补标。
4. 每批完成后重新读取标签并核对，记录成功与失败项。重复执行跳过已正确标注的文章；重试前检查标签是否被作者更新，避免覆盖新决策。
5. 误标时仅撤销本批对来源标签的变更，不用整份旧标签快照覆盖当前标签，也不改动其他文章内容。

标签变动会触发现有部署流程，因此按小批次执行并观察构建结果。即使首次发布时间不变，GitHub 的 Issue 更新时间也可能变化；实施前核对站点“文章更新”是否依赖该字段，确认不会把纯标签补标误展示为正文更新。

### 兼容与完成标准

- 未标注存量文章继续正常展示、进入归档与 RSS；首版沿用“没有来源标签”的展示，不生成隐含默认值。
- 来源标签页只收录明确标注的文章，不能把未标注文章并入人工标签页；两类数量之和不代表全部文章数量。
- 存量迁移完成指已盘点全部目标文章、补齐可确认项、单独记录未知项与冲突项，不要求强行达到 100% 标注率。
- 普通维护不强制为来源未知的旧文章补标；大幅重写后可以根据新的正文写作过程确定来源。
- 后续再次导入旧博客内容时，迁移脚本不得自动添加人工主写标签；只有明确来源映射才能写入来源标签。

## 验收标准

- 两个标签名称与描述明确，能按上述例子判断常见写作方式。
- 新文章只有一个来源标签，并保留导航标签。
- 读者能在现有文章标签位置看到来源，并通过对应标签页浏览文章。
- 未标注历史文章仍正常发布，不会被默认归类为人工写作。
- 修改来源标签不会改变文章永久链接或首次发布时间。
- 来源未知不被自动归为人工或 AI；存量补标保留现有正文、其他标签和发布状态，并有逐篇依据与变更记录。

## 后续可选改进

列表已采用独立徽章（人工主写 / AI 主写），并从列表主题标签行移除来源标签；首页精选、普通列表、标签页列表与归档共用徽章。未标注或双标签冲突时不展示徽章，避免错误归属；详情页同样在标题旁展示徽章，并从主题标签行移除来源标签；标签索引保留现有筛选机制。若后续升级为独立元数据，再明确标签迁移与兼容规则。首版不扩大到生成模型、提示词、AI 使用比例或自动检测。
